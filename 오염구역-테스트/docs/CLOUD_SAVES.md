# 계정 저장 및 다른 기기에서 이어하기

1. 기존 기록이 있는 브라우저에서 로그인한다.
2. 시작 화면의 **비회원 기록 가져오기**를 선택한다. 원본은 유지하고 계정에 별도 저장 슬롯을 만든다.
3. **계정에 저장했습니다. 다른 기기에서 이어 할 수 있습니다.** 안내를 확인한다.
4. 다른 브라우저 또는 모바일에서 같은 계정으로 로그인하고 **불러오기**를 선택한다.

회원 플레이 기록은 기기에 먼저 저장하고 5초 간격으로 서버 저장을 시도한다. 인터넷이 끊기면
같은 계정의 기기 사본에 대기 상태를 남기고 재시도한다. 업로드 완료 전 브라우저 저장소를 지우면
서버에 전송되지 않은 변경을 복구할 수 없다. 시작 화면의 **계정 기록 동기화**로 즉시 재시도할 수 있다.

두 기기가 같은 기록을 수정하면 서버의 최신 기록을 유지하고 이 기기의 변경을 **충돌 사본**으로
별도 보관한다. 충돌 사본도 다음 동기화에서 계정에 저장된다. 삭제도 버전을 확인해 전파하며,
다른 기기에서 수정된 기록은 오래된 삭제 요청으로 지우지 않는다.

비회원 기록의 협동방 참가 권한은 계정으로 이전하지 않는다. 가져온 비회원 협동방 기록은 개인
기록으로 보관한다. 기존 협동방에는 계정으로 초대 코드를 사용해 참가해야 한다.
같은 회원 계정으로 플레이한 협동방 기록은 온라인 방 정보도 함께 보관한다.
사용자 초상화는 최대 512px PNG로 동기화한다.

## 구현과 검증

- 회원 로컬 사본: `user://account_rooms/<user_id>/`. 비회원 원본: `user://rooms/`.
- 서버: `account_saves`, `account_save_sync`. 본인 회원 토큰만 허용하고 직접 테이블 접근은 차단한다.
- 버전 비교를 서버 트랜잭션 안에서 수행한다. 응답 유실 후 동일한 내용의 재요청은 중복 버전을 만들지 않는다.
- `tests/cloud_saves.gd`: 두 기기 복원, 충돌, 업로드 도중 수정, 오프라인 재시도, 계정 분리, 삭제, 반복 가져오기, 초상화.
- `supabase/tests/account_saves.sql`: 실제 DB 권한·익명 거부·버전 충돌·재시도·삭제. 전체 트랜잭션 롤백.
- `tests/cloud_live.mjs`: 임시 회원의 실제 로그인 토큰 두 세션으로 REST 저장/복원·격리·충돌·삭제·CORS. 테스트 계정은 종료 시 삭제.

실제 PC·모바일 브라우저 두 대에서 UI 전체를 조작하는 수동 테스트는 별도로 확인해야 한다.
